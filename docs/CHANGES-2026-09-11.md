# Transcribe : correction du 504 Whisper

Les logs de production montrent un abandon Nginx après 60 secondes alors que
le backend retourne 200 après environ 137 secondes pour un audio de 169 secondes.

Le proxy API utilise désormais un délai de lecture et d’envoi de 900 secondes.
Ce délai est fini : les traitements ou files d’attente plus longs peuvent encore
échouer. Une API de tâches asynchrones reste préférable pour les longs médias.

La conversion et le calcul Whisper des routes Transcribe breton/gallois passent
dans le pool de threads. Un sémaphore limite ces traitements à un par processus ;
il ne couvre pas les autres applications ni plusieurs workers. Les contrôles
de santé et les autres routes peuvent ainsi continuer pendant le calcul.

Validation staging nécessaire : redéployer les fronts utilisant nginx-app.conf
et le backend, tester le média de 2 min 49, vérifier la réponse HTTP 200 et
la réactivité du backend pendant le traitement. Aucun déploiement automatique
ni transfert de données staging vers production n’est requis par ce correctif.
