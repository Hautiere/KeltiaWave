# Livraison KeltiaWave du 29 août 2026

## Résultat livré

KeltiaWave est désormais déployé sur OVH avec trois états indépendants :

- développement local ;
- staging protégé sur `*.staging.keltiawave.com` ;
- production publique sur `*.keltiawave.com`.

La production a été promue depuis une candidate isolée après sauvegarde de
l'installation historique, validation Caddy, émission des certificats TLS et
tests publics. Les anciens conteneurs sont volontairement conservés pendant la
période d'observation afin de permettre un rollback rapide.

## Fonctions et corrections

- Footer KeltiaWave commun sur toutes les applications, visible sans défilement
  vertical sur une vue PC lorsque la hauteur disponible le permet.
- Navigation du portail adaptée automatiquement à localhost, au staging et à la
  production, sans référence à une machine de développement dans les builds OVH.
- Backend FastAPI, comptes et rôles partagés entre Komz et Play.
- Profils de démonstration disponibles sur le staging et automatiquement
  désactivés en production (`DISABLE_TEST_ACCOUNTS=true`).
- Connexion unique du staging par cookie partagé entre tous les sous-domaines ;
  une seule saisie donne accès à toutes les applications pendant 12 heures.
- Correction de la course asynchrone de l'écran d'évaluation Komz : le texte ne
  peut plus être remplacé par la réponse tardive d'un autre audio.
- Stockage PostgreSQL et MinIO durable ; lecture vidéo compatible HTTP Range.
- Modèles Vosk breton, Whisper breton et Whisper gallois montés en lecture seule
  depuis `/home/ubuntu/apps/keltiawave-models`.

## Données validées

Les tests bloquent une livraison qui ne contient pas au minimum :

- 105 phrases Komz ;
- 4 leçons Play ;
- 4 vidéos Play ;
- une réponse HTTP Range vidéo exacte de 1024 octets.

La migration initiale a également conservé les audios, validations, segments,
trous et vocabulaire présents dans les sources locales validées.

## Déploiement OVH

Le code est toujours produit par `git archive` depuis une révision Git connue :
les secrets, données locales et modifications non commitées ne sont jamais
inclus dans une livraison.

### Staging

```bash
SSH_TARGET=ubuntu@vps-dc75d8a6.vps.ovh.net \
  ./scripts/deploy-staging-ovh.sh --apply
```

L'import local initial utilise exceptionnellement `--with-local-data`. Les
livraisons suivantes réutilisent les volumes persistants du staging.

### Candidate production

```bash
SSH_TARGET=ubuntu@vps-dc75d8a6.vps.ovh.net \
  ./scripts/deploy-production-candidate-ovh.sh --apply
```

Cette commande clone PostgreSQL et MinIO depuis le staging vers des volumes
`production` distincts, puis exécute les tests sur les ports loopback
`24100` à `24600`.

### Promotion

```bash
SSH_TARGET=ubuntu@vps-dc75d8a6.vps.ovh.net \
PUBLIC_IPV4=51.178.38.152 \
  ./scripts/promote-production-ovh.sh

SSH_TARGET=ubuntu@vps-dc75d8a6.vps.ovh.net \
PUBLIC_IPV4=51.178.38.152 \
  ./scripts/promote-production-ovh.sh --apply
```

Le premier appel est un dry-run. Le second sauvegarde l'ancienne production,
valide et recharge Caddy, attend jusqu'à cinq minutes les certificats TLS,
contrôle tous les domaines et restaure automatiquement l'ancien Caddyfile si un
test échoue.

## DNS

La zone OVH utilise deux wildcards A vers `51.178.38.152` :

```text
*.keltiawave.com
*.staging.keltiawave.com
```

Le wildcard staging, plus spécifique, reste prioritaire pour ses sous-domaines.
Les domaines racines `keltiawave.com` et `keltiawave.bzh` restent déclarés
séparément.

## Sauvegardes et rollback

- Sauvegardes de clonage : `shared/backups/production/before-staging-clone-*`.
- Sauvegardes avant promotion : `shared/backups/pre-promotion-*`.
- Chaque sauvegarde de promotion contient le Caddyfile historique, PostgreSQL,
  MinIO, les données de l'ancienne application et `SHA256SUMS`.
- L'ancienne pile n'est pas supprimée lors de la promotion.
- Ne jamais utiliser `docker compose down --volumes` sur staging ou production.

## Suite envisagée

La première déclinaison mobile prévue est une PWA **KeltiaWave Record**. Elle
réutilisera l'interface responsive de `record.keltiawave.com` et ajoutera le
manifest, les icônes, l'écran de lancement et le service worker nécessaires à
l'installation sur l'écran d'accueil. Cette PWA n'est pas encore implémentée.
