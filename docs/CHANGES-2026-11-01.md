# Corrections du 1er novembre 2026

## Accès natif Android au staging

L’accès privé de test Record ne couvrait pas Live ou Transcribe. Le même appareil
provisionné peut désormais appeler une liste fermée de routes médias sur le seul
hôte `record.staging.keltiawave.com` : capacités Live, amélioration Whisper,
estimation et transcription des fichiers Vosk/Whisper breton/gallois.

Le WebSocket Live utilise un ticket opaque à usage unique, valable 20 secondes,
obtenu via un POST authentifié à `/api/mobile/live-ticket`. Le secret de l’appareil
n’est jamais placé dans l’URL ou les protocoles WebSocket. Le ticket est transmis
via un sous-protocole dédié, consommé par l’authentification staging, puis retiré
avant le backend ; seul `keltiawave-live` est négocié. Les tickets sont bornés en
mémoire et invalidés au redémarrage. Un ticket consommé ou expiré est refusé.

La session navigateur staging et l’authentification de production restent
inchangées. Les contrôles couvrent les méthodes, hôtes, origines, chemins et
paramètres autorisés ; les en-têtes mobiles ne sont pas envoyés à d’autres URLs.

## Mobile

- Transcribe propose Vosk serveur par défaut pour le breton ; le bouton n’est
  plus désactivé en dur. Le gallois reste sur Whisper.
- Le scénario import MP3 puis transcription est vérifié avec un fichier simulé.
- L’export texte Transcribe utilise désormais le même enregistrement natif dans
  Téléchargements/KeltiaWave que Record.
- L’APK de test doit être réinstallé ; modifier le site seul ne met pas l’app à jour.

L’envoi email direct est activé sur le staging avec le service SMTP existant.
Les tests automatisés n’envoient aucun email réel ; l’utilisateur déclenche son
propre envoi depuis le formulaire de l’app. Aucun secret ni APK n’est commité.
